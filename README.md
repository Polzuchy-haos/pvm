# PVM — Pico Virtual Machine

Маленькая стековая виртуальная машина, спроектированная специально для
микроконтроллеров и встраиваемых систем: минималистичное ядро на C (без
динамической памяти, пригодное для вшивания прямо в прошивку), собственный
ассемблер и небольшой C-подобный высокоуровневый язык, компилирующийся в тот
же байткод.

> **Разработано с использованием ИИ.** Значительная часть кода в этом
> репозитории написана в паре с ИИ-ассистентом (Claude): архитектурные решения
> принимались человеком, реализация, тесты и документация — совместно. Всё, что
> касается работы с железом, проверялось на реальной плате STM32G071, а не
> только в симуляторе.

## Структура репозитория

- [`pvm/`](pvm/) — ядро ВМ (`pvm.h`/`pvm.c`): стек, полный набор инструкций
  (арифметика, биты, переходы, память), вызов PVM-функций через `ENTER`/
  `LEAVE`/`LOADFP`/`STOREFP`, вызов в Си-код через `SVC`. Это единственная
  часть проекта, которая реально попадает в прошивку МК — компилируется как
  есть, без изменений.
- [`compilator/`](compilator/) — низкоуровневый ассемблер `pvmc`
  (`.pvms` → байткод: сырой `bin`, Intel HEX для прошивки, C-массив для
  вшивания без файловой системы, листинг с картой памяти — где лежит каждая
  функция и переменная) и дизассемблер `pvmdisasm`.
- [`hlc/`](hlc/) — компилятор небольшого C-подобного высокоуровневого языка
  `pvmcc` (`.hlc` → текст `.pvms`, дальше идёт через `pvmc` без единой
  правки). Функции, локальные переменные, `if`/`while`/`for`, глобальные
  массивы, MMIO-переменные, `import`, `extern` (вызов ассемблерных функций),
  `svc(...)` (вызов в Си), устранение мёртвого кода, объявление размеров
  памяти целевой ВМ через `section` — выход за границы секции ловится на
  этапе компиляции, а не в рантайме на устройстве, включая оценку худшей
  глубины стека по графу вызовов.
- [`simulator/`](simulator/) — `pvmsim`: исполняет скомпилированный байткод,
  печатает трассировку по каждой инструкции; здесь же (`pvmenv.c`) живут
  демонстрационные обработчики `SVC` (время, печать, сложение) и блок
  периферии, общие с отладчиком.
- [`debugger/`](debugger/) — `pvmdbg`: интерактивная сессия отладки в
  терминале — шаг, точки останова по строкам `.hlc`, просмотр стека,
  дизассемблер. Общается со «стороной устройства» (`pvm/pvmdbg.c`,
  компилируется в прошивку) кадрами протокола, см.
  [`docs/debugger.md`](docs/debugger.md).
- [`tools/vscode-pvm/`](tools/vscode-pvm/) — расширение VS Code: подсветка
  синтаксиса и отладка `.hlc` прямо в редакторе (точки останова кликом,
  F5/F10/F11, стек в панели переменных) поверх той же `pvmdbg`.
- [`lib/`](lib/) — небольшая стандартная библиотека для `.hlc`
  (`mathlib.hlc`, `time.hlc` — учёт времени с корректной обработкой
  переполнения счётчика).
- [`example/`](example/) — примеры программ на обоих языках, от простого
  «мигания светодиодом» до вызова ассемблерной функции из высокоуровневого
  кода.
- [`docs/`](docs/) — описания языков и инструментов:
  [`docs/pvms-language.md`](docs/pvms-language.md) (ассемблер),
  [`docs/hlc-language.md`](docs/hlc-language.md) (высокоуровневый язык),
  [`docs/debugger.md`](docs/debugger.md) (отладчик и его протокол).
- [`Release/`](Release/) — папка для раздачи: собранные инструменты, ядро ВМ в
  исходниках, `lib/`, документация и расширение VS Code. Целиком собирается
  `make`-ом и в git не хранится (кроме своего
  [README](Release/README.md)) — всё её содержимое и так есть в репозитории,
  только в исходном виде.

## Сборка

```
make            # или: cmake -S . -B build && cmake --build build
make test       # ctest — прогон всех примеров с проверкой результатов
make run        # собрать и запустить симулятор на примере по умолчанию
```

## Пример

```c
// blink.hlc
import time;

volatile int LED @ 0x4000;

void main() {
    LED = 0;
    while (1) {
        LED = LED ^ 1;
        Time_Delay(1);
    }
}
```

```
pvmcc blink.hlc -o blink.pvms
pvmc blink.pvms -o blink.bin
pvmsim blink.bin
```

Подробнее про оба языка — в [`docs/hlc-language.md`](docs/hlc-language.md) и
[`docs/pvms-language.md`](docs/pvms-language.md); про сами инструменты — в
[`Release/README.md`](Release/README.md).
