# PVM — готовые бинарники

Здесь лежат собранные инструменты тулчейна PVM (Windows, статически слинкованы
с libgcc/libstdc++ — запускаются без установки MinGW), а рядом всё, что нужно,
чтобы этой папки хватило самой по себе: документация, исходники ядра ВМ,
стандартная библиотека и расширение для VS Code.

**Папку целиком собирает `make`** (или `cmake --build build`) из корня проекта —
в git она не хранится, потому что всё в ней и так есть в репозитории, только в
исходном виде. Единственное исключение — этот README: он написан руками, а не
скопирован. Если чего-то не хватает или что-то устарело — просто пересоберите.

## pvm/ — ядро ВМ для вашей прошивки

Это единственная часть проекта, которая реально попадает в микроконтроллер.
Компилируется как есть, без изменений, без динамической памяти:

- `pvm.c` / `pvm.h` — сама виртуальная машина;
- `pvmdbg.c` / `pvmdbg.h` — отладочный агент: с ним `pvmdbg --port …` и
  расширение VS Code смогут отлаживать программу прямо на плате. Не нужен —
  просто не включайте эти два файла в сборку, ВМ от них не зависит.

Как встроить агента в прошивку (главный цикл, приём кадров из UART) —
в [`docs/debugger.md`](docs/debugger.md).

## Пайплайн

```
prog.hlc --[pvmcc]--> prog.pvms --[pvmc]--> prog.bin --[pvmsim]--> выполнение
                                         \-> prog.hex   (Intel HEX, для прошивки МК)
                                         \-> prog.c     (C-массив, для вшивания в прошивку)
                                         \-> prog.lst   (листинг: адрес + байты + мнемоника)

prog.bin --[pvmdisasm]--> дизассемблированный листинг (без исходника, только по байткоду)
prog.bin --[pvmdbg]-----> пошаговое выполнение: точки останова, шаг, просмотр стека
```

Если пишете сразу на ассемблере (`.pvms`) — пропускаете `pvmcc` и стартуете с `pvmc`.

## pvminit — генератор скриптов сборки и отладки

```
pvminit [каталог] [-m main.hlc] [-n имя] [-p COM3] [--tools каталог]
        [--make программа] [--no-vscode] [-f]
```

С него удобнее всего начинать свою программу: вместо того чтобы
выписывать вызовы `pvmcc` и `pvmc` со всеми флагами руками, он создаёт
готовый `Makefile` и `.vscode/`, уже знающие путь до этой самой папки
с утилитами:

```
pvminit myproject --port COM6
cd myproject
make run        # собрать и выполнить в симуляторе
make debug      # пошаговая отладка в ВМ
make board      # то же на плате
```

Создаёт `Makefile`, заготовку `main.hlc` (если своей программы ещё
нет), `.gitignore` и `.vscode/` с конфигурациями отладки (F5) и задачей
сборки (Ctrl+Shift+B). Файлы обычные и рассчитаны на то, что их будут
править дальше руками, поэтому уже существующий файл никогда не
перезаписывается без `--force`.

Запуск без аргументов настраивает текущий каталог, причём если в нём
уже лежит ровно один `.hlc` — именно он и станет главным исходником.

Путь к утилитам берётся из каталога, из которого запустили сам
`pvminit`, если утилиты лежат в нём (то есть `cd` сюда и запуск отсюда
привяжет проект именно к этой папке); иначе — из каталога, где лежит
`pvminit.exe`. Задать явно — `--tools`.

Требуется GNU make; как он называется на этой машине (`make`,
`mingw32-make`, `gmake`), `pvminit` определяет сам. Подробности — в
[`docs/project-generator.md`](docs/project-generator.md).

## pvmc — ассемблер (`.pvms` → байткод)

```
pvmc <input.pvms> [-o output] [-f bin|hex|carray] [-l [listing.lst]] [-g [map.dbgmap]]
```

- `-o output` — путь к результату. Без флага: имя входного файла с новым расширением
  (`.bin`/`.hex`/`.c` — в зависимости от `-f`).
- `-f bin` (по умолчанию) — сырой байткод.
- `-f hex` — Intel HEX (`:LLAAAATT...CC` с контрольной суммой) — то, что понимают
  прошивальщики МК.
- `-f carray` — файл `const uint8_t name[] = {...}; const unsigned name_len = N;`,
  чтобы вшить байткод прямо в прошивку без файловой системы.
- `-l [listing.lst]` — дополнительно сохранить листинг (адрес, hex-байты инструкции,
  исходная мнемоника/операнд — с именами меток и `.const`, а не голыми числами).
  Путь можно не указывать — тогда `<output>.lst`.
- `-g [map.dbgmap]` — карта отладки «адрес → файл и строка `.hlc`», её читает
  `pvmdbg`, чтобы показывать исходник. Пусто, если в `.pvms` нет директив
  `.line` (то есть для файлов, написанных на ассемблере руками).

Примеры:
```
pvmc example.pvms                          # example.bin
pvmc example.pvms -f hex -o example.hex
pvmc example.pvms -f carray -o example.c
pvmc example.pvms -l example.lst           # example.bin + example.lst
```

Синтаксис самого языка `.pvms` — в [`docs/pvms-language.md`](docs/pvms-language.md).

## pvmcc — компилятор высокоуровневого языка (`.hlc` → `.pvms`)

```
pvmcc <input.hlc> [-o output.pvms] [-I путь]...
```

Только один шаг пайплайна: превращает `.hlc`-исходник в текст ассемблера.
Результат — обычный `.pvms`, дальше с ним работает `pvmc` (см. выше). Без `-o`
результат кладётся рядом с исходником с расширением `.pvms`.

`import имя;` в `.hlc`-файле ищет `имя`/`имя.hlc` по порядку: рядом с
компилируемым файлом → `lib/` рядом с этим самым `pvmcc.exe` (она уже лежит
тут же, в `Release/lib/`) → каждый путь из `-I` (можно указывать флаг
несколько раз, проверяются в заданном порядке).

```
pvmcc program.hlc                        # program.pvms
pvmcc program.hlc -o out.pvms
pvmcc program.hlc -I ../common -I ../vendor
```

Описание языка — в [`docs/hlc-language.md`](docs/hlc-language.md).

## pvmdisasm — дизассемблер (байткод → мнемоники)

```
pvmdisasm <input.bin> [-o output.txt]
```

Читает уже скомпилированный `.bin` и печатает `адрес  hex-байты  MNEMONIC операнд`
для каждой инструкции — без исходника, поэтому имена меток/констант не восстанавливаются
(в отличие от листинга `pvmc -l`, дизассемблер видит только байты). Неизвестный байт
опкода печатается как `DB 0xXX`, не обрывая разбор. Без `-o` печатает в stdout.

```
pvmdisasm program.bin
pvmdisasm program.bin -o program.disasm.txt
```

## pvmsim — симулятор (исполняет байткод)

```
pvmsim [input.bin]
```

Загружает `.bin` и крутит его до `HALT`, ошибки выполнения или лимита в 100000 шагов
(защита от зависших программ), печатая трассировку каждой инструкции
(`адрес МНЕМОНИКА операнды -> результат  SP N`). Если путь не передан — пытается
запустить `bytecode_listing.bin` из каталога, где лежит рядом с ним пример сборки
(актуально только при запуске из дерева `build/`).

```
pvmsim program.bin
pvmsim program.bin --stack 256 --ram 128   # другие размеры пулов, в словах
```

Размеры стека и RAM задаются при запуске (`--stack`, `--ram`; по умолчанию
1024 и 64 слова, как `PVM_CFG_*` в `pvm/pvm.h`) — так же, как прошивка сама
выделяет пулы под свою плату: программу можно прогнать именно на тех размерах,
что будут на устройстве. `--steps N` меняет предел в 100000 инструкций.

Программа с `HALT` завершится с кодом 0 и словами `pvmsim: halted`; программа с
ошибкой выполнения (например, обращение по плохому адресу) — с ненулевым кодом и
сообщением об ошибке в stderr. Программы вида `while(1)` (например, `blink`) до
`HALT` не дойдут никогда — это нормально, так и задумано.

## pvmdbg — отладчик (пошаговое выполнение)

```
pvmdbg [program.bin]       # ВМ внутри процесса утилиты
pvmdbg --port COM3         # плата по последовательному порту, 9600 8N1 (--baud N — другая)
pvmdbg --port COM3 --map prog.dbgmap    # плюс строки исходника
```

В отличие от `pvmsim`, который прогоняет программу целиком, `pvmdbg` открывает
сессию и ждёт команд. Программа при этом остановлена на нулевой инструкции.

`Ctrl+C` работает как в gdb: во время выполнения останавливает программу и
возвращает приглашение, в приглашении — завершает сессию (как и `exit`).

| Команда | Кратко | Что делает |
|---|---|---|
| `run` | `r` | выполнять до точки останова или конца программы |
| `step` | `s` | одна инструкция |
| `pause` | `p` | остановить |
| `reset` | | вернуть в начало, очистить стек |
| `state` | `i` | где PC, SP, FP и почему стоим |
| `stack [n]` | | верхние `n` слов стека |
| `dis` | `d` | дизассемблировать от текущего PC |
| `break <куда>` | | точка останова: `break 0x12` или `break blink.hlc:21` |
| `clear <адрес>` | | снять |
| `breaks` | `b` | какие стоят |
| `help` | `?` | список команд |
| `exit` | `quit`, `q` | закончить сессию |

```
(pvmdbg) break 0x12
  0x0012 will stop the program
(pvmdbg) run
  pc=0x0012  sp=4  fp=1  breakpoint
  -> 0x0012  1A         ENTER
(pvmdbg) stack
  [0] 10      <- top
  [1] 7
```

Инструкция под `PC` показывается после каждой остановки автоматически; `dis`
печатает следующие за ней. Байты читаются с устройства, поэтому дизассемблер
показывает то, что реально исполняется, а не содержимое локального `.bin`.

Если рядом с `.bin` лежит карта отладки от `pvmc -g` (локально она находится
сама, по порту — указывается через `--map`), то вместе с инструкцией печатается
строка исходника, а точки останова можно ставить как `break blink.hlc:21`.

Адреса берутся из карты памяти в листинге (`pvmc … -l файл.lst`) — там указано,
с какого адреса начинается каждая функция и где лежит каждая переменная.

Вариант `--port` требует прошивки, в которую вкомпилирован `pvm/pvmdbg.c`
(отладочный агент) и слой приёма кадров из UART. Файл вместе с `--port` не
передаётся: у платы программа своя, уже залитая. Подробности протокола и что
нужно на стороне прошивки — в [`docs/debugger.md`](docs/debugger.md).
