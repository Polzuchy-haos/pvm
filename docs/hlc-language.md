# Высокоуровневый язык PVM (`.hlc`)

Маленький C-подобный язык, который компилятор `pvmcc` переводит в текст
ассемблера `.pvms` (см. `docs/pvms-language.md`) — дальше он идёт через
`pvmc` без единой правки. Компилятор сам считает раскладку кадра
(`ENTER`/`LEAVE`/`LOADFP`/`STOREFP`), расставляет метки для `if`/`while`/`for`
и подставляет адреса глобальных переменных — вручную это делать не нужно.

## Типы

Только один тип данных — `int` (16-битное знаковое слово, как `PVM_Word_t` в
ВМ). `void` — только как тип возврата функции, отдельного типа-переменной
`void` не существует.

## Глобальные переменные

```c
int COUNTER;                    // обычная переменная в RAM
int COUNTER = 5;                // с начальным значением (только целочисленный литерал)
volatile int LED @ 0x4000;      // жёсткая привязка к адресу — периферия/MMIO
int table[10];                  // массив в RAM (без инициализатора)
```

`@адрес` — переменная живёт по фиксированному адресу (обычно периферия,
`>= 0x4000`), а не в авто-выделяемой ячейке RAM. Обычные (без `@`) глобальные
переменные и массивы компилятор сам раскладывает по RAM подряд, начиная с
адреса `0`, и проверяет, что они помещаются в `PVM_CFG_RAM_SIZE`.

Инициализатор допускается только у скалярных не-`volatile` глобальных и
только как константный целочисленный литерал (не выражение) — компилятор
подставляет запись значения в начало `main`.

## Функции

```c
int square(int x) {
    return x * x;
}

void increment() {
    LED = LED + 1;
}

void main() {
    ...
}
```

- `main` обязателен и должен быть объявлен ровно как `void main()` — без
  параметров и без возвращаемого значения. Причина: `main` — точка входа
  (`.entry main`), у неё нет вызывающего и, соответственно, некуда возвращать
  результат обычным `RET`; выход из `main` (явный `return;` или просто конец
  функции) компилируется в `HALT`, а не в `RET`.
- Любая другая функция с `return expr;` на всех путях выполнения, если она не
  `void`; `void`-функция не может возвращать значение (`return;` — можно).
- Аргументы передаются по значению, только `int`. Количество аргументов в
  вызове обязано совпадать с объявлением — иначе ошибка компиляции.
- Рекурсия поддерживается — каждый вызов получает свой кадр (`ENTER`/`LEAVE`).

## Локальные переменные — важное ограничение

```c
void f() {
    int a;        // OK — самое начало функции
    int b = 1;    // OK
    a = 2;        // дальше — обычные операторы, ещё один "int" здесь уже нельзя
}
```

**Все локальные объявления обязаны идти единым блоком в самом начале тела
функции**, до любого другого оператора (правило в духе C89) — включая тело
`if`/`while`/`for` и `for`-инициализатор: там объявлять локальные нельзя,
только использовать уже объявленные вверху. Это не забытая фича, а осознанное
ограничение: раскладка локальных на `FP` — статическая (компилятор один раз
на этапе компиляции решает, какой переменной какое смещение соответствует), и
это верно только если каждое объявление гарантированно выполняется ровно один
раз за вызов функции. Объявление внутри цикла или условия исполнялось бы
переменное число раз и рассинхронизировало бы адресацию остального кадра.

**Локальных массивов не бывает** — только глобальные. `LOADFP`/`STOREFP`
берут константное смещение, а не индекс со стека, поэтому массив на стеке
кадра адресовать нечем; массив в RAM адресуется как `база + индекс` через
`LOADI`/`STOREI`, что и делает компилятор для глобальных массивов.

Блочной вложенности/тени переменных нет: имена локальных и параметров функции
— в одном плоском пространстве имён на всю функцию.

## Операторы

```c
{ ... }                              // блок
if (cond) stmt [else stmt]
while (cond) stmt
for (простой_оператор?; cond?; простой_оператор?) stmt
return [expr];
halt;
имя = expr;
имя[индекс] = expr;
имя(аргументы);                      // вызов как оператор
```

## Выражения и операторы (по убыванию приоритета)

| Приоритет | Операторы | Ассоциативность |
|---|---|---|
| низший | `\|\|` | слева направо |
| | `&&` | слева направо |
| | `==` `!=` | слева направо |
| | `<` `>` `<=` `>=` | слева направо |
| | `\|` | слева направо |
| | `^` | слева направо |
| | `&` | слева направо |
| | `<<` `>>` | слева направо |
| | `+` `-` | слева направо |
| | `*` `/` | слева направо |
| высший | унарные `-` `!` `~` | справа налево |

Плюс индексация `arr[i]` (только для глобальных массивов), вызов функции
`f(...)`, скобки `(expr)`, целочисленные литералы (`123`, `0x7B`).

`&&`/`||` — **с коротким замыканием**, как в C (правая часть не вычисляется,
если результат уже известен по левой), результат всегда нормализован к `0`
или `1`. Присваивание — только как оператор верхнего уровня внутри
`простой_оператор` (`a = b = 5` и `if ((a = f()) != 0)` не поддерживаются),
но как выражение оно **возвращает присвоенное значение** (поэтому его можно
использовать, например, в `for`-шаге).

## Комментарии

`// до конца строки` и `/* блок */` — как в C (независимо от `#`-комментариев
`.pvms`, у языка свой лексер).

## Чего сознательно нет в этой версии

- Типов кроме `int`/`void` (нет `char`, `bool`, `float`, указателей, `struct`).
- Локальных массивов (см. выше) и многомерных массивов.
- Блочной области видимости/тени переменных.
- Присваивания как части произвольного выражения.
- Анализа "все ли пути функции возвращают значение" — компилятор просто
  всегда добавляет `LEAVE`/`RET` (или `LEAVE`/`HALT` для `main`) в конец тела
  функции, даже если до этого уже был явный `return` на всех путях
  (недостижимый код на пару байт, не баг).

## Пример целиком

```c
int arr[5];
int SUM;

void fill() {
    int i;
    for (i = 0; i < 5; i = i + 1) {
        arr[i] = i * 2;
    }
}

int total() {
    int i;
    int sum;
    sum = 0;
    for (i = 0; i < 5; i = i + 1) {
        sum = sum + arr[i];
    }
    return sum;
}

void main() {
    fill();
    SUM = total();   // 0+2+4+6+8 = 20
}
```

Больше примеров: `example/square.hlc` (аргумент + возврат), `example/counter.hlc`
(MMIO + `while`), `example/blink.hlc` (бесконечный цикл + программная задержка),
`example/arrays_and_logic.hlc` (массивы, `for`, все сравнения, `&&`/`||`).

## Диагностика ошибок

Компилятор останавливается на первой ошибке и печатает `файл:строка: error:
сообщение` в stderr, код возврата `1`. Проверяются: неизвестные
идентификаторы/функции, несовпадение числа аргументов, использование `void`-
функции как значения, локальные объявления не в начале функции, локальные
массивы, переполнение RAM глобальными, `main` с параметрами или не `void`, и
т.д.
